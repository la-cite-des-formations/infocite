Note de Cadrage : Sous-rubrique 'Agenda'

Document d'aide à la décision — Synthèse révisée intégrant les retours du Responsable Technique

Contexte : L'objectif est d'ajouter une sous-rubrique "Agenda" au sein de la rubrique principale "Événements". Cette page présentera une ligne du temps (timeline) chronologique des événements futurs. Cette note détaille les choix techniques arrêtés, les évolutions de base de données validées, les fonctionnalités additionnelles retenues et l'analyse comparative visuelle.

1. Architecture Base de Données (Option B retenue)

Conformément aux validations, l'architecture s'appuie sur une structure relationnelle à deux tables afin de garantir une modularité maximale.

Avantages : Permet d'associer un nombre illimité de dates (sessions) à un même article éditorial sans duplication de contenu. Elle sépare proprement la partie éditoriale des informations temporelles d'événement et permet de catégoriser les événements avec une couleur dédiée.

Migration de la table event_types (Types d'événements)

Schema::create('event_types', function (Blueprint $table) {
    $table->increments('id');
    $table->string('name', 100);
    $table->string('color', 7); // Code hexadécimal (ex: #E67E22)
    $table->timestamps();
});

Migration de la table events

Schema::create('events', function (Blueprint $table) {
    $table->increments('id');
    $table->unsignedInteger('post_id')->index();
    $table->unsignedInteger('event_type_id')->index();
    
    // Dates et heures séparées pour une flexibilité totale
    $table->date('start_date');
    $table->time('start_time')->nullable();
    $table->date('end_date')->nullable();
    $table->time('end_time')->nullable();
    
    // Lieu physique ou virtuel
    $table->string('location', 150)->nullable();
    $table->timestamps();

    $table->foreign('post_id')->references('id')->on('posts')->onDelete('cascade');
    $table->foreign('event_type_id')->references('id')->on('event_types');
});

2. Fonctionnalités Additionnelles Validées

Illustration par vignette (Thumbnail)

Lorsqu'un événement est rendu sur la timeline, le système cherche la galerie photo associée à l'article ($post->gallery). Si elle existe, la première image (triée par le champ order) est récupérée et affichée sous forme de vignette (90x90px) à gauche du descriptif.

Code d'accès : $thumbnailPath = $post->gallery ? $post->gallery->sortedImages()->first()['path'] : null;

Puces de couleur dynamiques & Administration

Chaque type d'événement configuré en base de données dispose d'une couleur. La timeline affichera la puce ou l'icône de l'événement avec cette teinte.

Liste initiale des types d'événements à injecter :

• Événement interne • Événement externe • Concours • Salon & forums
• Conférence • Portes ouvertes • Remise des diplômes • Jobs dating / Info
• Afterworks • Séminaire • Réunions institutionnelles • Rencontres professionnelles

Une interface d'administration simplifiée sera intégrée dans le back-office pour permettre d'ajouter/éditer ces types et d'y associer leur couleur à l'aide d'un sélecteur HTML5 (ColorPicker).

Recommandation d'intégration

Nous recommandons l'utilisation de la Timeline Bootstrap Verticale comme vue par défaut de l'Agenda (Scénario B) car elle valorise parfaitement le contenu éditorial, les images des articles et s'affiche à la perfection sur mobile.

Cependant, pour satisfaire le besoin d'une vision synthétique de type calendrier, nous proposons d'intégrer dans un onglet secondaire ou via un bouton de bascule un calendrier mensuel standard via la version gratuite de FullCalendar.
